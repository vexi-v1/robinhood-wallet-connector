# Robinhood Wallet provider

`@vexi/robinhood-wallet` provides a framework-independent EIP-1193 provider and a dedicated Robinhood Wallet connection dialog for frontend applications. It is the shared core behind this toolkit's wagmi, RainbowKit and Web3-Onboard adapters.

Built and maintained by **[Vexi Lab](https://vexi-protocol.ai) (an onchain options protocol)**. This is an independent community project, **not an official Robinhood SDK**, and is not affiliated with or endorsed by Robinhood.

This package is currently unpublished. Build the repository and install `vexi-robinhood-wallet-0.1.0.tgz` generated by `npm pack`; see the [repository installation guide](https://github.com/vexi-v1/robinhood-wallet-connector#install-from-this-repository). ESM and TypeScript declarations are included. Node.js 22.12 or newer is the development baseline; wallet interaction runs in the browser.

## Minimal browser usage

```ts
import { RobinhoodProvider } from '@vexi/robinhood-wallet';

const provider = new RobinhoodProvider({
  projectId: 'YOUR_WALLETCONNECT_PROJECT_ID',
  chains: [1],
  rpcMap: { 1: 'https://ethereum-rpc.publicnode.com' },
  metadata: {
    name: 'My app',
    description: 'My app description',
    url: 'https://my-app.example',
    icons: [],
  },
});

// Wire these functions to user controls in your application.
async function connectWallet() {
  try {
    const { accounts, chainId } = await provider.connect({ chainId: 1 });
    return { accounts, chainId };
  } catch {
    // Present a local error or retry control. Do not log pairing material.
    return undefined;
  }
}

async function disconnectWallet() {
  await provider.disconnect();
}
```

Constructing the provider does not request accounts, initialize the remote transport, or open a dialog. Invoke `connect()` or `eth_requestAccounts` only after the user chooses to connect. A real WalletConnect project ID with the application's origin allowed is required for remote pairing.

## Options

| Option | Meaning |
| --- | --- |
| `projectId: string` | WalletConnect project ID used when remote transport is needed. |
| `chains: readonly number[]` | Nonempty list of configured EVM chain IDs. The first initializes the local chain value. |
| `optionalChains?: readonly number[]` | Additional configured EVM chain IDs offered to the wallet. |
| `rpcMap?: Record<number, string>` | RPC endpoints used for supported read requests through the remote provider. |
| `metadata` | Application `{ name, description, url, icons }`. Supply an HTTP(S) application URL. |
| `showModal?: boolean` | Defaults to `true`. Set `false` only when the host handles connection links and cancellation. |
| `connectTimeoutMs?: number` | Attempt timeout, default `120000`. |
| `discoveryTimeoutMs?: number` | Injected-provider discovery window, default `200`. |
| `storagePrefix?: string` | Isolates this connector's persisted session state; defaults to a project-ID-based prefix. |

Both chain arrays form the offered remote namespace. They are not a claim that Robinhood supports all entries, and approval of every configured chain is not required. `connect({ chainId })` requires approval of that specific configured chain. Remote operations also require the relevant session permission.

Give distinct independent connector instances distinct stable `storagePrefix` values. Reusing a prefix intentionally shares the persisted session namespace. Keep the prefix stable across reloads when session recovery is desired.

## API

| API | Behavior |
| --- | --- |
| `connect({ chainId? }?)` | Returns `{ accounts: string[], chainId: number }`. Opens the remote dialog if no matching injected provider is found. |
| `request({ method, params? })` | EIP-1193 request. `eth_requestAccounts` starts connection; `eth_accounts` reads the local cache; `eth_chainId` returns a hexadecimal chain ID. Other requests require a connection. |
| `cancel()` | Cancels the pending attempt and closes its dialog. Does not disconnect an established connection. |
| `disconnect()` | Cancels pending work, clears local account/session selection, and disconnects this transport's approved remote session. Injected wallet permissions are not revoked. |
| `destroy()` | Releases this provider's UI and listeners. Preserves an approved persisted session for a later provider instance; does not revoke it. The destroyed instance cannot reconnect. |
| `isAuthorized()` | Attempts to recover this connector's previously approved session without requesting account permission. Returns `boolean`; may initialize remote transport to inspect saved state. |
| `getAccounts()` | Returns a copy of the current cached accounts, or an empty list before connection/recovery. |
| `getChainId()` | Returns the local numeric chain ID. Before connection, this is the first configured chain, not a wallet confirmation. |
| `status` | `idle`, `connecting`, or `connected`. |
| `transport` | `injected`, `walletConnect`, or `undefined`. |
| `connected` | Whether this instance has adopted a connection. |
| `on(event, listener)` / `removeListener(event, listener)` | Subscribe to or remove a provider event listener. |

No connection method automatically requests a signature or submits a transaction. The generic `request()` API can forward signing or transaction methods only when an application explicitly requests them and the connected wallet/session supports them. Wallet approval and rejection remain wallet decisions.

### Events

The provider emits `connect` with `{ chainId: string }`, `accountsChanged` with an account array, `chainChanged` with a hexadecimal string, `disconnect`, and forwarded `message` events. Remote pairing emits `display_uri` with sensitive WalletConnect pairing material.

Keep connection state current through events instead of assuming a connection remains valid indefinitely. Remove your listeners when the host component is disposed. A changed chain or empty account list must be handled by the host application.

### Retry and cancellation

Matching concurrent core connection requests share the current attempt; a conflicting requested chain is rejected. Closing the SDK dialog or pressing Escape rejects the pending attempt with code `4001`. A timeout also terminates the attempt. Late remote approval is cleaned up for its original session topic instead of adopting it after cancellation.

The default error view keeps a Close action and explains how to retry from the application. Call `connect()` again from a new host action to create a fresh request. The framework adapters retain their framework's normal error and connection state.

### Custom connection UI

With `showModal: false`, subscribe to `display_uri` before connecting and handle the link in your own UI. Use exported `getRobinhoodUri(uri)` to validate a WalletConnect v2 URI and construct the `robinhood-wallet://wc?uri=...` app link. Launch that link only after an explicit user action.

Your UI must offer cancellation through `provider.cancel()`, clear its QR/link on close and completion, and ignore results from an obsolete attempt. Do not send pairing URIs to QR services, analytics, logs, or error-reporting systems. The default modal generates its QR in the browser and clears the URI and canvas when closed.

`ConnectionModal` and `ProviderDependencies` describe the internal host/test seams. `RobinhoodModal` is an implementation detail, not a public package export.

## Discovery and session scope

Discovery checks the published `com.robinhood.wallet` EIP-6963 identity and the `isRobinhoodMobileWallet` injected-provider flag. It does not select an arbitrary `window.ethereum` provider and change its label. These hints distinguish compatible provider advertisements; they are not cryptographic vendor authentication.

Remote connections use `@walletconnect/sign-client` **2.26.0**. The core owns its approved session topic and requests only within its authorized EVM namespace. Read calls use the corresponding configured `rpcMap` endpoint. The SDK uses browser persistence where available, while WalletConnect maintains its own session/key storage. A restored session is validated for expiry and approved accounts/chains before adoption.

Imports and construction are safe without a browser. Interactive use requires a browser; the default modal requires native `HTMLDialogElement.showModal()`. CSS is included in the lazy modal module, and the icon is an embedded data URL. A restrictive Content Security Policy must permit the module's inline styles and image data URLs, or the application should supply its own UI.
