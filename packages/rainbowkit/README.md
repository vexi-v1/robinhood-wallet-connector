# Robinhood Wallet for RainbowKit

> **AI integration docs:** [llms.txt](https://raw.githubusercontent.com/vexi-v1/robinhood-wallet-connector/main/llms.txt) · [Integration guide](https://raw.githubusercontent.com/vexi-v1/robinhood-wallet-connector/main/docs/ai-integration.md)

Add a Robinhood Wallet entry to RainbowKit with the toolkit's dedicated connection dialog.

Built and maintained by **[Vexi Lab](https://vexi-protocol.ai) (an onchain options protocol)**. This is an independent community project, **not an official Robinhood SDK**, and is not affiliated with or endorsed by Robinhood.

These packages are not published to npm. Follow the [tarball installation guide](https://github.com/vexi-v1/robinhood-wallet-connector#install-from-this-repository) before using this adapter.

Add Robinhood first in your wallet list:

```ts
import { connectorsForWallets } from '@rainbow-me/rainbowkit';
import { injectedWallet, walletConnectWallet } from '@rainbow-me/rainbowkit/wallets';
import { robinhoodWallet } from '@vexi/robinhood-wallet-rainbowkit';

const connectors = connectorsForWallets([
  { groupName: 'Recommended', wallets: [robinhoodWallet] },
  { groupName: 'Other wallets', wallets: [injectedWallet, walletConnectWallet] },
], {
  projectId: 'YOUR_WALLETCONNECT_PROJECT_ID',
  appName: 'My app',
  appUrl: 'https://my-app.example',
});
```

Pass `connectors` to wagmi's `createConfig`, then use the ordinary `WagmiProvider`, `QueryClientProvider`, `RainbowKitProvider`, and `ConnectButton`. The complete runnable app is in `examples/rainbowkit`.

This adapter targets **RainbowKit 2.2.11 + wagmi 2.19.5**. RainbowKit currently declares a wagmi v2 peer; the separate wagmi adapter supports the tested v3 baseline, but that does not imply RainbowKit v3 compatibility.

Selecting Robinhood opens the SDK's native top-layer dialog, with its own close, Escape, and app-opening controls. Close it and select Robinhood again to retry. The underlying wallet chooser remains inert until the SDK dialog closes. This deliberately omits RainbowKit's `qrCode` and `mobile` hooks: RainbowKit's native Back navigation has no public cancellation callback for a pending wallet proposal. A second pairing modal or a private controller patch is unnecessary.

RainbowKit always passes a chain to wagmi's `connect`. The wagmi adapter treats it as a preference, as wagmi's built-in connectors do: if the wallet session does not approve that chain, or the in-app wallet cannot switch to it, the connection stays on the wallet's chain instead of failing. Only a user rejection of the switch fails the connection.

The adapter consumes `walletConnectParameters.metadata` generated by `connectorsForWallets`. Other generic WalletConnect provider options are not forwarded: this package owns its session transport and lifecycle. Configuration order controls the recommended group; RainbowKit may show installed or recent wallets before it according to its own settings.

For server-rendered applications, always supply an absolute HTTP(S) `appUrl` to `connectorsForWallets` as shown above. The direct `robinhoodWallet` factory also accepts `appUrl` and `appDescription`, or an explicit `walletConnectParameters.metadata` object. This lets `createConfig`, `getProvider`, and `isAuthorized` run without `window` and without requesting accounts. Browser-only applications may omit the URL to use the current origin; a factory created on the server without a URL cannot initialize a provider until a valid URL is supplied.

A displayed QR code is not proof of physical-wallet approval or network support.
